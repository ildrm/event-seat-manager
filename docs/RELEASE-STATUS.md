# وضعیت انتشار event-seat-manager 2.0.0

**شماره و هویت بسته نهایی شده‌اند؛ پذیرش کامل محصول برای فروش عملیاتی هنوز تکمیل نشده است.** تغییر شمارهٔ نسخه و ساخت ZIP جایگزین پیاده‌سازی قابلیت‌های باقی‌مانده یا آزمون درگاه و محیط مقصد نیست.

## وضعیت طراح سالن نسخهٔ دوم

۵۰ چیدمان، مدل داده و موجودی ۱۵۰هزار جایگاه، رزرو مشترک تکی/میز/جایگاه، قیمت دسته‌ای، بلیت گروهی، نقشه/فهرست مشترک و پیش‌نمایش سه‌بعدی پیاده شده‌اند. مهاجرت افزایشی ۱۸ به ۱۹ و آزمون واقعی وردپرس/ووکامرس/InnoDB اجرا شده است. آزمون ۱۰۰۰ درخواست هم‌زمان، صحت موجودی و صدور را تأیید کرد؛ هدف تأخیر رزرو و موجودی در سخت‌افزار محلی برآورده نشد. بنابراین ساخت جلسه‌های جدید `allocated` تا پذیرش محیط مقصد بسته است؛ دسترسی بلیت‌ها و رزروهای موجود وابسته به این دروازه نیست. [راهنما و قرارداد پذیرش](VENUE-DESIGNER.md) و [شواهد آزمون نسخهٔ دوم](VENUE-ACCEPTANCE.md) و گزارش‌های `docs/qa/venue-*.json` محدودیت را ثبت می‌کنند.

## تحویل این بررسی

- نام عمومی، پوشه، فایل اصلی و text domain: `event-seat-manager`؛ نسخهٔ محصول و بلوک‌ها: `2.0.0`.
- `CHANGELOG.md` خالی است و تاریخچه‌های پیشرفت/انتشار قدیمی حذف شده‌اند. راهنماها وضعیت فعلی را توضیح می‌دهند.
- داده‌های `pesm_`، شورت‌کدها و مسیر API حفظ شده‌اند؛ schema مستقل نسخهٔ19 دارد. نسخهٔ قبلی باید پیش از فعال‌سازی بستهٔ جدید غیرفعال شود؛ بارگذاری دو نسخه هم‌زمان مهار شده است.
- رابط و پیام‌ها در فارسی و انگلیسی، جهت متناسب با زبان، کاتالوگ PHP/JavaScript و فایل‌های استاندارد ترجمه آماده شده‌اند.
- نقص تطبیق مبلغ پرداخت، زمان بررسی انقضا پس از انتظار قفل، آمار رزرو منقضی، آدرس REST در پیوند یکتای ساده، حفظ فوکوس نقشه و چند اشکال بومی‌سازی اصلاح شده‌اند.
- ساخت تکرارپذیر ZIP، checksum، آزمون‌های مستقل، تست واقعی وردپرس/ووکامرس/InnoDB و بررسی مرورگر به مخزن اضافه شده‌اند.

## شواهد جاری

جزئیات و تعداد دقیق بررسی‌ها در [QA](QA-REPORT.md)، [آزمون یکپارچه](INTEGRATION-RESULTS.md)، [رابط](REVIEW-FRONTEND.md) و [دوزبانگی](REVIEW-LOCALIZATION.md) ثبت می‌شوند. سناریوهای هم‌زمان با20فرایند واقعی برای تک‌صندلی، ظرفیت آزاد و کنترل ورود بررسی شده‌اند. مسیرهای منتخب سفارش با هر دو ذخیره‌ساز CPT و HPOS ووکامرس آزموده شده‌اند؛ Checkout Blocks رسمی پشتیبانی نمی‌شود.

## موانع تکمیل محصول مطابق پرامپت

| مانع | وضعیت |
|---|---|
| Checkout Blocks / Store API و سفارش یکپارچهٔ چندجلسه‌ای | مسیر اختصاصی موجود است؛ یکپارچه‌سازی استاندارد کامل نیست |
| فایل PDF بومی بلیت در دو زبان | چاپ مرورگر وجود دارد؛ renderer بومی کامل نیست |
| فروش تجاری بستهٔ مشترک چندجلسه‌ای | تنها گروه‌بندی اختیاری بلیت‌های موجود وجود دارد |
| جابه‌جایی صندلی با اختلاف قیمت | انتقال هم‌قیمت وجود دارد؛ تسویهٔ اختلاف کامل نیست |
| تفویض مستقل یک رویداد داخل مرکز و چرخهٔ کامل حریم خصوصی | کنترل مرکز وجود دارد؛ این بخش‌ها کامل نیستند |
| درگاه واقعی، تسویه/استرداد، SMTP و ملی‌پیامک | سرویس‌های واقعی با اعتبارنامهٔ آزمون پذیرش نشده‌اند |
| بار گسترده، قطع اجباری worker، همهٔ مهاجرت‌های تاریخی و دستگاه‌های هدف | آزمون‌های منتخب وجود دارد؛ پوشش کامل عملیاتی تکمیل نشده است |

این موارد در [ماتریس نیازمندی‌ها](REQUIREMENTS.md) و [نقشهٔ تکمیل](ROADMAP.md) پنهان یا کامل اعلام نشده‌اند. قابلیت‌های آزمایشی بدون پذیرش مستقل نباید صرفاً با تغییر شمارهٔ نسخه فعال شوند.

## حکم تحویل

بستهٔ نصب‌شوندهٔ `event-seat-manager-2.0.0.zip` برای بررسی و پذیرش آماده است. عبارت «تمام محصول مطابق پرامپت برای فروش عملیاتی تأیید شده» دربارهٔ این خروجی صحیح نیست. پیش از انتشار تجاری باید موانع بالا رفع و در محیط مقصد پذیرش شوند.
