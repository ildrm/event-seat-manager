# قرارداد نام شرکت‌کنندگان — نسخه ۰٫۱۶

## محدودیت و مالکیت

موجودی صندلی و ظرفیت فقط از موتور رزرو خوانده می‌شود. فرم HTML نام شرکت‌کنندگان **موجودی یا قیمت را تعیین نمی‌کند**. داده‌های نام مهمان شخصی‌اند و در سفارش WooCommerce و بلیت نگهداری می‌شوند؛ به API عمومی دیگران پاسخ داده نمی‌شوند. پشتیبانی از سیاست نگه‌داری/حذف داده‌ها و فرم‌های سفارشی مدیریتی هنوز ناقص است.

## نمونه درخواست صندلی‌دار

```json
{
  "session_id": 12,
  "first_name": "علی",
  "last_name": "خریدار",
  "phone": "09123456789",
  "attendees": [
    {"seat_id": 21, "first_name": "سارا", "last_name": "احمدی"},
    {"seat_id": 22, "first_name": "رضا", "last_name": "کریمی"}
  ]
}
```

هدر `X-PESM-Hold-Token` باید همان توکن نگهداری معتبر باشد. مجموعه `seat_id` باید **دقیقاً** با مجموعه صندلی‌های Hold یکی باشد. آرایه خالی، تکرار یا کمبود صندلی رد می‌شود. کلیدهای دیگر مجوز تغییر ظرفیت ایجاد نمی‌کنند.

## ظرفیت بدون شماره صندلی

هر عنصر آرایه `attendees` حاوی `first_name` و `last_name` است؛ ترتیب آرایه، شماره بلیت از ۱ تا تعداد ظرفیت نگهداری‌شده را تعیین می‌کند. تعداد عناصر باید دقیقاً برابر `hold.quantity` باشد. شناسه صندلی در این حالت مجاز نیست.

## تکرار درخواست و سازگاری

در درخواست تکراری با همان Hold دارای سفارش، اطلاعات شرکت‌کنندگان جدید **روی سفارش قبلی نوشته نمی‌شود** و اطلاعات immutable سفارش موجود معیار صدور است. سفارش‌های قدیمی بدون متای `_pesm_attendees_v1` با نام خریدار ادامه می‌یابند. تغییر نام پس از صدور، فرایند ویژه و ثبت حسابرسی مستقل می‌خواهد که هنوز پیاده نشده است.

## وضعیت آزمون

آزمون‌های خالص PHP، حالات نام نامعتبر، شناسه جعلی/تکراری، تعداد متفاوت و بازخوانی snapshot را پوشش می‌دهند. آزمون‌های GA رایگان و پولی با FakeDB، نام فردی بلیت‌ها را بررسی می‌کنند. هیچ آزمون واقعی WordPress/WooCommerce/InnoDB/مرورگر در این محیط اجرا نشده است.
