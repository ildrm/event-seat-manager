# ADR-0002 — مرز WooCommerce و موجودی صندلی

**وضعیت:** طرح معماری، implementation در آینده.

WooCommerce حقیقت سفارش/مالیات/پرداخت/استرداد و PESM حقیقت ظرفیت، تخصیص، بلیت و ورود است. از Woo CRUD استفاده شود و HPOS/Blocks فقط پس از تست اعلام شوند. پرداخت و رزرو، تراکنش توزیع‌شده واحد ندارند: Saga، outbox/idempotent callback و reconciliation الزامی‌اند. Callback دیرهنگام اگر seat reallocated شده است، نباید به زور آن را پس بگیرد؛ سفارش به رسیدگی/استرداد هدایت شود. **این قرارداد هنوز پیاده نشده است.**
