# Frontend, interaction and accessibility review — 1.0.0

Owners: frontend engineering, map interaction, Persian/English UX, integrations and accessibility review (R09, R10, R11, R14, R20). The acceptance target is that public booking interfaces render in the site's language, preserve dynamic user content, and allow keyboard selection in a large layout.

## Findings addressed

- Public JavaScript constructed relative endpoints with `new URL(path, restRoot)`. With WordPress plain permalinks, this discarded `?rest_route=...` and loaded an HTML page, leaving the map unusable. All public booking, ticket recovery, transfer, cart and gate requests now use the shared `PESM_restURL` builder. Report endpoints already use complete URLs generated by WordPress.
- Static PHP and JavaScript messages, Elementor labels and Gutenberg metadata now use the shared language catalog. Dynamic event titles, attendee names, layout labels and other user content remain outside translation calls. The catalog build checks coverage. Runtime statuses receive controlled enum labels while unknown WooCommerce custom statuses remain intact. Admin report requests use WordPress's user-locale parameter so an English administrator on a Persian site also receives translated API errors.
- Containers follow the selected locale's direction. CSS uses logical alignment; map coordinates remain left-to-right to preserve the layout. English dates use Gregorian dates in Tehran time, and Persian dates use the existing Jalali formatter. JavaScript number/date formatting receives BCP 47 locale tags.
- Rebuilding 900 seat buttons previously discarded keyboard focus after each selection and polling update. The map now preserves the focused seat, uses a single seat tab stop and arrow navigation, and keeps a visible focus outline. Coarse-pointer devices retain a minimum scale that avoids tiny seat targets in the initial overview.
- Collapsed event sessions now defer map/capacity initialization until opened. Seat availability polling pauses while the session panel is closed, avoiding the eager creation and polling of many 900-seat maps on one event page.
- Incomplete inventory responses no longer treat unreported seats as available. The server remains the authority for every hold and change.
- General-admission payment links now receive the same same-origin check as the seated checkout. Capacity timers stop when leaving the page.
- Ordinary event/session creation headings no longer carry obsolete preview version labels. Feature-specific restrictions remain visible where functionality is still conditional or incomplete.

## Verification

- `php tests/frontend-locale-unit.php`: English/Persian public views, direction, block metadata, preserving and escaping user titles, and translation script dependencies.
- `node tests/frontend-rest-url.js`: pretty/plain REST roots, subdirectory installations, endpoint query parameters, existing root parameters and rejecting absolute endpoint paths.
- Existing isolated Elementor registration and WooCommerce cart bridge regressions passed. PHP and JavaScript syntax checks passed for edited files.
- Native Chrome against the disposable local WordPress installation: the 900-seat public map initially exposed the REST URL defect; after repair it loaded prices and inventory. Finding A-12, pressing Space, Right and Space selected A-12 and A-13. Creating a temporary hold showed a 600-second timer and the English buyer/attendee forms; releasing it succeeded. English ticket/recovery interfaces rendered, and a synthetic invalid bearer returned an English access-denied message without ticket data. Persian public map labels, currency formatting, RTL alignment, search and keyboard selection were also verified. The event page showed Jalali dates in Tehran time; opening a general-admission session loaded its capacity, and a temporary guest capacity hold and release succeeded. Opening a seated session initialized its map.

- After explicit user approval, the disposable administrator signed in successfully. The Persian dashboard and English dashboard (using the QA user's locale) were visually inspected, including presets, translated statuses and version 1.0.0. The visual hall editor loaded a 900-seat layout and its English controls without saving any changes.

## Limits

This review does not certify all browsers, physical mobile devices, assistive technologies, real payment gateways, SMTP/SMS providers or every theme/page builder. The current cart uses its dedicated order form; native WooCommerce Checkout Blocks integration remains outside the verified scope.
